# Repository instructions

Jimix is our entry for the Patterno "Watchtower" challenge (`docs/Patterno-Track-Description.pdf`):
attach unknown public-procurement portals, deliver their open tenders and documents, notice when a
portal breaks, and repair it, with a dashboard for operators.

## Working together (read this first)

Several humans and agents on different machines work on this repo at once. Coordination happens over git
on the orphan branch **`coord`**, which holds only `PROTOCOL.md` (rules and the current goal),
`BOARD.md` (the shared todo list with claims) and `CHANNEL.md` (an append-only message log).

1. Check it out next to your working copy once:
   `git fetch origin coord && git worktree add ../jimix-coord coord`
2. Read `../jimix-coord/PROTOCOL.md` and follow it. It can change at any time: run `git pull` in
   `../jimix-coord` before you pick work and after you finish, and re-read `PROTOCOL.md` whenever it
   changed (`git log -1 -- PROTOCOL.md`).
3. How to test a change: `docs/testing.md`.

When you start a session in this repo, ask your operator (the human you work for) once whether they want
to devote resources to the current operation described in `PROTOCOL.md`. If your tool supports it,
offer to join as a background subagent so your main task isn't interrupted. Don't join without a yes.

The protocol, the board and the current focus are changed on `coord`, not here. This file only says
where to find them.

## Layout

- `backend/` — FastAPI API and the Watchtower engine (Python 3.13+, its own `pyproject.toml` and `uv.lock`).
  - `app/main.py` — the API from the PDF (`/portals`, `/refresh`, `/tenders`, `/runs`, `/files/{sha256}`).
  - `app/watchtower.py` — runs reads and repairs, moves portals between `integrating`, `serving`,
    `healing` and `failed`, saves tenders.
  - `app/agent.py` — the LLM agent (OpenAI-compatible Chat Completions with tools) that writes a recipe.
  - `app/discovery.py` — automatic API-doc probing and API-path scanning of a site's scripts.
  - `app/recipe.py` — the declarative recipe format (JSON, never code), applying it, normalizing to the
    spec's tender fields, the health check. `app/keywords.json` holds the multilingual keyword lists.
  - `app/fetch.py` — HTTP client: one request per second per site, robots.txt, public addresses only,
    login/captcha detection, streamed downloads with size and per-run limits.
  - `app/browser.py` — Playwright rendering (headless Chromium) through the same rate limit.
  - `app/documents.py` — document download, ZIP unpacking, storage by sha256.
  - `app/registration.py` — portal location lookup (RDAP/WHOIS) for the dashboard map.
  - `app/schema.sql` — SQLite tables: `portal`, `portal_location`, `run`, `recipe` (history, one active),
    `tender` (spec JSON in `data`).
  - `tests/` — pytest suite with fake portals; no network, no paid model calls.
- `frontend/` — Next.js dashboard. `frontend/AGENTS.md` is generated by `next dev`.
- `docker-compose.yaml` — runs the frontend container.
- `docs/` — the challenge PDF and `testing.md`.

## Commands

- Backend setup, from `backend/`: `uv sync --extra dev` and `uv run playwright install chromium --only-shell`.
- Backend server, from `backend/`: `uv run python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`.
  It reads `OPENAI_API_KEY` from the environment or `.env` at the repository root.
- Backend tests, from `backend/`: `uv run --extra dev python -m pytest -q`. Lint: `uvx ruff check .`.
- Frontend, from `frontend/`: `npm ci`, then `npm run dev`. In Docker: `docker compose up --build --wait`
  from the repository root.
- Settings are environment variables; the README lists them.

## Conventions

- Keep code plain and small: simple SQL, few abstractions, no docstrings, comments only where needed.
- Ruff with `line-length = 110` (`backend/pyproject.toml`); keep `uvx ruff check .` clean.
- Recipes stay declarative data. Never add a feature that makes the model's output executable.
- Every request to a portal must go through `Fetcher` or `browser.render`, so the one-request-per-second
  rule from the PDF holds. Never log or store API keys.
- Agent memory files (`MEMORY.md` and similar) are personal notes: never commit them. They are git-ignored.
